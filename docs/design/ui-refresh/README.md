# UI Refresh Verification Notes

## Design direction

RGate's surrounding chrome is treated as a compact precision instrument framing
an uninterrupted schematic canvas:

- **Surface hierarchy**: cool-neutral chrome (`#f4f6f8` light, `#161c25` dark)
  and crisp 1 px borders (`#c7d0dc` light, `#3c4a5e` dark) separate toolbars,
  sidebars, and the bottom drawer from the schematic drawing surface without
  adding card chrome or sacrificing canvas area.
- **State clarity**: active tools use a blue accent fill with a 1 px primary
  outline; inactive Undo/Redo/Stop toolbar controls use GPUI Kit's disabled
  state; simulation status pairs a Play/Pause icon with text (`Running` /
  `Paused`) rather than a color-only dot.
- **Typography & density**: preserves the default 16 px GPUI Kit base scale,
  compact 32 px toolbar height, and existing saved panel dimensions so zoom and
  schematic area remain unchanged (`113%` at 1240×820, `63%` at 1020×620).
- **Electrical color fidelity**: Classic and Modern canvas styles remain
  independent of Light/Dark appearance. Low, high, unknown, high-impedance,
  selected wires, and buses keep distinct colors, adjusted only where needed to
  meet contrast targets on light canvas backgrounds.
- **Waveform instrument chrome**: the time ruler and signal gutter have a subtle
  tinted header and 1 px divider; when no probes are active, the vertical
  divider stops at the ruler so the empty-state prompt stays unobstructed.

## Contrast audit

See `contrast.txt` (generated by `scripts/ui-contrast.py`). All audited normal
UI text and schematic signal pairs meet `>= 4.5:1` sRGB contrast, and all
audited focus, input border, selected border, and running indicator pairs meet
`>= 3.0:1`.

## Automated vs. visual/interaction verification

- **Automated Cargo checks/tests**:
  - `cargo fmt --all -- --check`
  - `cargo check -p rgate`
  - `cargo test -p rgate-core -p rgate-editor -p rgate-sim -p rgate-ui --lib`
    (includes `rgate_sim::tests::full_adder_truth_table`, verifying all 8 input
    combinations of the full adder)
  - `scripts/build-web.sh` (WASM release web bundle)
  - `python3 scripts/docs-links.py`
  - `python3 scripts/ui-contrast.py`
- **Visual & coordinate-driven browser checks** (GPUI renders to a WebGPU canvas,
  so Playwright screenshots are inspected visually rather than validated via DOM
  assertions):
  - `interactions/01-search.png` through `interactions/08-paused-probe.png`
    exercise component search (`xor`), placement, undo, redo, selection, wiring,
    panel-resize persistence (`interactions/persistence.json`: `sidebar_width:
    240` preserved across reload), running simulation, pausing, and probing.

## Known limitations

- At minimum `1020×620` with the default `bottom_height` (176 px), the waveform
  toolbar scrolls horizontally and only one trace row fits until the user drags
  the horizontal splitter upward (preserved intentionally so saved panel sizes
  are not altered).
- In the web build, the static `Licenses` overlay link in `web/index.html`
  slightly overlaps the rightmost coordinate readout in the status bar at narrow
  widths (pre-existing web shell overlay).
- Native desktop GPUI rendering was verified via `cargo check -p rgate` and unit
  tests; visual screenshots were captured from the WASM/WebGPU build.
